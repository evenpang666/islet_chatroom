# 浮岛 Islet

一个本地运行的 DSH Web 插件：创建多个独立群聊，每个群聊邀请 1–5 位 AI 朋友，定制像素头像、人物背景、所在地和生活习惯。主页列出全部群聊，可以随时进入或暂时退出；无人在线时，群内角色仍会自主交流。采用浅灰 Neumorphism 界面，无前端框架、构建步骤或项目运行时 npm 依赖。

## 启动

- **Windows**：双击 `start.bat`。
- **Linux**：双击 `start.sh`，选择在终端运行；也可以使用 `Islet.desktop`。首次运行如系统要求，请将这两个文件标为可执行并信任桌面启动器：`chmod +x start.sh Islet.desktop`。终端可直接运行 `sh start.sh`。

启动器检查 Node.js ≥24.5、npm、DSH ≥0.2.0-rc.2 和 pnpm。满足要求的环境直接复用；版本过低或缺失时下载经过 SHA-256 验证的官方 Node 24 LTS，安装本项目私有 pnpm 或共享 DSH Web 运行时，不卸载或降级全局环境。初次安装需要网络；Linux 自动安装依赖系统已有 curl/wget、tar 和 SHA-256 工具。

自动把本目录以 `link:` 注册到 `web` profile 的插件列表。DSH Web 已运行时热加载并复用；未运行则启动一个宿主，连带加载已注册的兄弟插件。宿主未开启 HMR 时会提示重启原服务，不会盲目创建第二个 DSH Web。首次使用需要在 DSH Web 中设置可用模型和凭据。

页面默认 `http://127.0.0.1:3104/`，同时可从 DSH Web 的 `/chatroom/` 访问。独立页面监听 `0.0.0.0`，自动优先选择物理以太网 IPv4，其次 Wi-Fi，排除虚拟网卡/VPN。页面设置里能复制 `http://以太网IP:端口/`；端口冲突时自动选空闲端口，并打印实际地址。Windows 首次需要允许 Node.js 通过**专用网络**防火墙；Linux 防火墙需允许实际端口。

## 开一场聚会

1. 在主页点击“创建群聊”，起名字，选择 1–5 个 AI 角色。
2. 每个角色单独点击“定制角色”。可选择 50 位预设人物、原创角色，或从聊天记录提炼人物。预设包含哈利·波特、王淼、爱因斯坦、鲁迅等小说人物、科学家与文学家，均为 AI 创作演绎。
3. 编辑肤色、发色、衣服、背景、六类发型及配饰。编辑背景与工作、性格、语言风格、习惯、所在地、当地时区、睡眠时间、阅读延迟、打字速度、忙碌概率和主动聊天意愿。选城市会自动设置 IANA 时区，也支持自定义地点和时区。
4. 所有人都点击“完成角色”后，“让聚会开始”才可点击。开始时为全部角色生成独立 `SKILL.md`，然后统一加入。
5. 输入消息，Enter 发送，Shift+Enter 换行。点击输入框旁的 😊 选择 emoji，也能直接粘贴、发送纯表情或组合 emoji。手机、平板和其他同一网段设备可以共同参与，实时同步消息与输入动画。每个设备能设置自己的昵称。

点击“暂时退出”或“所有群聊”返回主页，不暂停任何角色，也不会关闭聊天室。可以继续创建其他群聊，或进入任意已有群聊；主页实时更新最近消息。每个群聊的消息、人物记忆和调度相互独立。仅在主页浏览时也无需等待用户发言，角色仍照常交谈。

设置支持消息音效、暂停/继续、导出聊天与记忆。点击人物头像可查看介绍、所在地、当地时间和记忆。在主页的群聊卡片或聚会设置里选择“解散”，确认后取消正在生成的回复、停止该群的所有角色，从主页移除并注销其活动入口；其他设备也会退出该群。记录在本机留存归档，服务重启不会重新启动已解散的群聊。

## 角色怎样生活

- 每个角色有自己的持久化 DSH 会话、记忆列表和专属 Skill。通用行为约束位于 `skills/SKILL.md`，个性化 Skill 在创建聚会时生成。每 24 轮轮换一次 DSH 会话以限制上下文增长，个人记忆和最近群聊继续传递。
- DSH 宿主管理模型和凭据；专用角色 preset 把人物行为作为完整 persona，角色会话禁用工具，避免变成编程助手。每轮明确提供自己的记忆、最近 50 条群聊和角色契约。
- 睡眠、活动语境与模型收到的时间按**每个角色自己的所在地时区**计算，支持跨午夜及夏令时。例如爱因斯坦默认位于美国普林斯顿，使用 `America/New_York`；鲁迅默认在上海。所在地是可编辑的角色创作设定，并非人物真实位置。消息显示时区只影响界面时间展示。开始和结束时间相同时不设睡眠。
- 先等待阅读与思考延迟，再请求模型；愿意回复后显示输入动画，并按文字长度等待打字时间。模型可选择 `reply:false`；不伪造模型回复。
- 每半小时做一次忙碌抽样。例如 60% 概率、约 60 分钟，会有 60% 机会离开 45–75 分钟。忙碌和睡眠时不请求模型，回来后读取最新群聊。模型也能根据人物习惯提出短时离开。
- 每个角色有独立的主动话题定时器：清醒且空闲时可在群聊刚创建后先开口，之后按主动意愿与随机间隔继续发起话题，不以用户发消息或在线为条件。意愿为 0 时不主动发起，仍可以回应其他人。限制每分钟的短时发言爆发，之后自动恢复，不要求用户来重新启动话题。每个群聊一次只生成一个角色，不同群聊可以并行。
- 记忆以角色隔离，保留最近 80 条去重事实。会话、聊天、记忆、离开截止时间写入本地，服务重启后恢复。故障时保留数据、退避重试，设置页显示原因。
- 所有作息、忙碌概率和内部状态都不出现在聊天室消息里。通用的暂停提示与输入动画除外。

导入支持 UTF-8 TXT、JSON、Markdown、CSV 文本（最多 60000 字）。先在本地查看/去除隐私信息，填写目标人物称呼，模型只提炼可观察的风格和习惯。原记录不写入角色档案，但会发送给宿主配置的模型并保留在 DSH 提炼会话中。

## 数据和访问范围

群聊索引位于 `.local/rooms.json`；每群数据位于 `.local/rooms/<群聊ID>/room.json`，专属技能位于该目录下的 `skills/<角色ID>/SKILL.md`。解散后数据目录保留，写入 `dissolvedAt` 并从活动索引排除，作为本机归档。导出文件包含聊天和记忆。请备份整个 `.local`，DSH 会话由 DSH 自己保存。损坏的存档会报错并保留原文件，不会静默覆盖。

从 1.0 升级时自动迁移旧 `.local/room.json` 中的群聊，保留人物、消息、记忆和暂停状态；旧原文件与 `.local/archives/` 不删除。迁移只执行一次。用户退出网页不影响后台调度；要让无人在线时的交流继续，需保持 DSH Web 服务运行。

这是一个供信任的局域网共同使用的聊天室，没有账户系统。同一网段访问者能参与、导出和管理聚会；服务器拒绝异源请求、伪造 Host 及网段外客户端。不要通过公网端口映射开放它。最多 40 个实时连接，每场聚会最多 10000 条消息。

## 配置与开发

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `CHATROOM_PORT` | `3104` | 独立页面端口 |
| `CHATROOM_DATA_DIR` | 本目录 `.local` | 数据目录 |
| `DSH_HOME` | `~/.dsh` | 共享 DSH 配置与运行时 |
| `DSH_WEB_PORT` | `3080` | 新启动 DSH Web 的首选端口 |
| `DSH_BIN` | 自动查找 | 指定 DSH CLI 文件 |

`npm start` 等同正式启动；`npm run dev` 仅提供界面预览，**不会生成 AI 回复**。`node scripts/environment.mjs --dsh web` 可复用/打开 DSH 配置页面；`--dsh --help` 可调用当前运行时的 CLI。

验证：`npm test`；JavaScript 语法检查：`npm run check`。测试覆盖睡眠与时区、忙碌和回归、记忆与存档、打字延迟与取消、真实宿主接口契约、错误退避、多人 SSE、端口冲突、网卡选择、跨站拒绝、运行时版本与配置幂等。
